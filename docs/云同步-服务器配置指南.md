# 云同步 —— 服务器配置与实施方案

> 目标：给 **Android App** 做任务数据云同步。
> 服务端放在**阿里云香港**，只服务 APK，**不需要 ICP 备案**。

---

## 0. 先说结论：要买什么

| 项目 | 选什么 | 大概多少钱 |
|---|---|---|
| 服务器 | 阿里云**轻量应用服务器**，地域选**中国香港**，2核2G | 约 ¥60~100/月（看活动） |
| 系统 | **Ubuntu 24.04 LTS** | 免费 |
| 域名 | 任意 `.com` / `.top` / `.cn` | 约 ¥30~60/年 |
| HTTPS 证书 | **Let's Encrypt**（自动续期） | 免费 |

**为什么不用 ECS**：轻量应用服务器更便宜、自带防火墙面板、配置简单，这个项目完全够用。

**为什么选香港**：大陆地域的域名必须 ICP 备案，香港不用。代价是延迟高一点（大陆访问约 30~60ms），对打卡同步完全无感。

## 1. 买服务器（控制台操作）

1. 登录阿里云 → 搜「**轻量应用服务器**」→ 立即购买
2. **地域**：选 **中国香港**（⚠️ 这一步选错就要备案了）
3. **镜像**：选 **系统镜像 → Ubuntu → 24.04**
4. **套餐**：2核2G / 40GB SSD / 3Mbps 起步即可
5. **时长**：先买 **1 个月**试水（香港不需要 3 个月，那是备案的要求）
6. 设置 root 密码（**记下来**）
7. 创建完成后，在实例详情页记下**公网 IP**

> 💡 阿里云经常有「新用户特惠」，香港轻量有时能到 ¥24/月，买之前先看看活动页。

---

## 2. 开放端口

轻量应用服务器有**独立的防火墙**（不是安全组），在实例详情页 → **防火墙**：

| 端口 | 协议 | 用途 | 必须 |
|---|---|---|---|
| 22 | TCP | SSH 登录 | ✅ |
| 80 | TCP | HTTP（申请证书时验证用） | ✅ |
| 443 | TCP | HTTPS | ✅ |

默认一般已开放 22/80/443，**确认一下**。不要开其它端口。

## 3. 连上服务器

Windows 用 **PowerShell**（自带 ssh，不用装 PuTTY）：

```powershell
ssh root@你的公网IP
```

第一次会问 `Are you sure you want to continue connecting?` → 输 `yes` → 再输密码。

> 密码输入时**屏幕不显示任何字符**，这是正常的，输完直接回车。

**验证**：浏览器打开 `http://你的公网IP`，应该看到 **Welcome to nginx!**

## 7. 域名解析

在阿里云 → **云解析 DNS** → 找到你的域名 → **解析设置** → 添加记录：

| 字段 | 填什么 |
|---|---|
| 记录类型 | `A` |
| 主机记录 | `sync`（最终域名是 `sync.你的域名.com`） |
| 解析线路 | 默认 |
| 记录值 | **服务器公网 IP** |
| TTL | 600 |

**验证**（等 1~10 分钟生效）：

```bash
ping sync.你的域名.com
```

应该返回你的服务器 IP。

> 域名在哪买的都行（阿里云/腾讯云/Namesilo），只要能把 A 记录指过来。

## 8. 配置 nginx 反向代理

我们的 Node 服务监听 `127.0.0.1:3000`，nginx 负责对外提供 443。

**新建配置文件**：

```bash
vim /etc/nginx/sites-available/daily-sync
```

**贴进去**（把 `sync.你的域名.com` 换成你的）：

```nginx
server {
    listen 80;
    server_name sync.你的域名.com;

    # 同步数据可能有点大，放宽一点
    client_max_body_size 2m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }
}
```

**启用并检查**：

```bash
ln -s /etc/nginx/sites-available/daily-sync /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default      # 删掉默认站点，避免抢 80 端口
nginx -t                                    # 必须显示 syntax is ok
systemctl reload nginx
```

## 9. 申请 HTTPS 证书

```bash
certbot --nginx -d sync.你的域名.com
```

交互式提示：

| 提示 | 选什么 |
|---|---|
| Enter email address | 你的邮箱（证书快过期会提醒） |
| Agree to the Terms of Service | `A` |
| Share your email with EFF | `N`（不需要） |
| Redirect HTTP to HTTPS | **`2`（Redirect）** |

**certbot 会自动改 nginx 配置**，把 80 跳转到 443，并配置好证书路径。

**验证**：

```bash
curl -I https://sync.你的域名.com
```

应该返回 `HTTP/2 200` 或 `502`（502 是因为 Node 服务还没起，正常）。

**续期**：certbot 装好时会自动加一个 systemd timer，证书 90 天有效，到期前自动续。手动检查：

```bash
certbot renew --dry-run
```

## 10. 部署同步服务

### 10.1 上传代码

```bash
mkdir -p /opt/daily-sync
cd /opt/daily-sync
```

把服务端代码传上来。三种方式，选一种：

**方式 A：scp（在你 Windows 电脑上跑）**

```powershell
scp -r .\server\* root@你的IP:/opt/daily-sync/
```

**方式 B：git clone（推荐，方便更新）**

```bash
cd /opt/daily-sync
git clone https://github.com/你的账号/仓库.git .
```

**方式 C：直接在服务器上写**（文件少的话）

```bash
vim /opt/daily-sync/server.js
```

### 10.2 装依赖并启动

```bash
cd /opt/daily-sync
npm install --production
node server.js       # 先前台跑一下，看有没有报错
```

看到 `listening on 3000` 就说明起来了，`Ctrl+C` 停掉，改用 pm2 托管。

### 10.3 用 pm2 守护

```bash
npm install -g pm2

cd /opt/daily-sync
pm2 start server.js --name daily-sync
pm2 save                  # 保存当前进程列表
pm2 startup               # 开机自启（会打印一行命令，照着执行）
```

**常用命令**：

```bash
pm2 list                  # 看状态
pm2 logs daily-sync       # 看实时日志
pm2 restart daily-sync    # 重启
pm2 stop daily-sync       # 停止
```

## 12. 备份

SQLite 是单文件，备份就是复制文件。

```bash
mkdir -p /opt/backup
crontab -e
```

**加一行**（每天凌晨 4 点备份，保留 30 天）：

```
0 4 * * * cp /opt/daily-sync/data.db /opt/backup/data-$(date +\%F).db && find /opt/backup -name "data-*.db" -mtime +30 -delete
```

> ⚠️ crontab 里的 `%` 必须转义成 `\%`，否则会被当成换行符。

## 13. 服务端接口设计

### 13.1 数据结构

```sql
CREATE TABLE IF NOT EXISTS syncs (
  code        TEXT PRIMARY KEY,   -- 同步码，用户的唯一标识
  payload     TEXT NOT NULL,      -- 整个账号容器 JSON
  updated_at  INTEGER NOT NULL,   -- 服务器最后更新时间（毫秒）
  device_id   TEXT,               -- 最后写入的设备
  device_name TEXT
);
```

**为什么存整块 JSON 而不是拆表**：
- 数据量极小（一年约 36 KB）
- 客户端数据模型改动时，服务端不用跟着改
- 合并逻辑在服务端做，但操作的是 JSON 对象

### 13.2 接口

**`GET /api/health`** → `{ "ok": true }`

**`POST /api/sync`**

请求：

```json
{
  "code": "7K3M9QX2P4WD",
  "deviceId": "a1b2c3",
  "deviceName": "小米14",
  "payload": { "version": 5, "activeId": "a...", "accounts": [...] }
}
```

响应：

```json
{
  "payload": { "version": 5, "activeId": "a...", "accounts": [...] },
  "serverTime": 1760961600000,
  "merged": { "fromServer": 12, "fromClient": 3, "conflicts": 0 }
}
```

`payload` 是**合并后的结果**，客户端直接用这个覆盖本地。

### 13.3 合并规则

| 情况 | 处理 |
|---|---|
| 某天只有客户端有 | 用客户端的 |
| 某天只有服务端有 | 用服务端的 |
| 某天两边都有 | 比 `updatedAt`，取**晚的** |
| `tasks`（今天） | 同一天的规则 |
| 设置类（结算时间等） | 比 `updatedAt`，取晚的 |
| `customHolidays` | 按 `date` 去重合并 |

**⚠️ 前提：`history` 每条记录必须有 `updatedAt` 字段。**

没有这个字段就只能按「完成数多的赢」，那样你在 A 上**取消勾选**会被 B 的旧记录覆盖回去。

## 14. 安全清单

- [ ] root 密码用 16 位以上随机串
- [ ] 防火墙只开 22 / 80 / 443
- [ ] 全站 HTTPS，不允许明文 HTTP（certbot 的 Redirect 选项会处理）
- [ ] 服务端不存任何个人信息（只有同步码 + 打卡数据）
- [ ] 同步码当密码保管，别截图外发
- [ ] 定期 `apt upgrade` 更新系统
- [ ] 备份文件别放在网站根目录

**关于同步码**：
12 位 base32（去掉易混的 0/O/1/I）≈ 60 bit 熵。暴力猜需要 10^18 次尝试，不可能。但如果码泄露，别人就能读写你的数据——所以**换设备时用复制粘贴，别用截图发微信**。

## 15. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `ssh: connect timed out` | 防火墙没开 22 | 控制台 → 防火墙 → 加规则 |
| `Permission denied (publickey)` | 用了密钥登录但没配 | 控制台重置 root 密码 |
| 域名 ping 不通 | A 记录没生效 | 等 10 分钟；用 `nslookup` 查 |
| `nginx -t` 报错 | 配置语法错 | 检查 `server_name` 后的分号 |
| certbot 卡住 | 80 端口不通 | 确认防火墙 + nginx 在跑 + 域名已解析 |
| App 里请求失败 | 证书问题 | Android 9+ 禁止明文；确认是 `https://` 且证书有效 |
| `502 Bad Gateway` | Node 服务没起 | `pm2 list` 看状态，`pm2 logs` 看报错 |
